# 净室重写规约（Clean-Room Rewrite Protocol）

本目录用于记录「合成配方生成器 / 渐变文字 / AI 模组翻译」三个功能的**独立重写过程**。
背景：这三个功能最初于 2026-08 引入时参考了第三方项目（Axolotl Launcher，GPLv3）的实现，
相关代码已在本仓库中替换。为了让替换过程可核查，本目录按下列规约记录。

## 为什么需要规约

GPLv3 约束的是**代码表达**（及其衍生作品），不约束**功能与思想**。
因此合规路径是：功能保留，代码由**未接触过原实现的人**、仅依据**公开规范**重新实现。

## 三步流程

1. **规格（spec）**——只看公开资料写出行为规格：
   - 语言/平台规范：JVMS《Java Virtual Machine Specification》第 4 章、ZIP/APK 容器格式、JSON 标准
   - 游戏与生态文档：Minecraft 数据包配方 JSON 结构、各聊天插件公开语法文档（MiniMessage / MineDown / CMI / TrChat / TabooLib / RoseGarden / MOTD / BBCode）
   - 我们自己的界面需求（由 UI 反推的输入输出契约）
   - 规格里**不出现**任何第三方实现细节（函数名、数据结构、私有前缀、注释）
2. **实现**——只依据 spec 编码，不参考原实现；对外行为由 spec 的验收用例锁定
3. **验收**——spec 里的每条用例都要有对应测试；行为变化必须先改 spec 再改代码

## 证据链

| 证据 | 位置 |
|---|---|
| 行为规格（含格式语法表与验收用例） | 本目录三份 `*.md` |
| 规格 → 实现的提交 | `refactor(cleanroom): …` 开头的提交 |
| 验收测试 | 各模块 `__tests__/` 与 `*_test.rs` |
| 历史说明 | 仓库根 `ACKNOWLEDGEMENTS.md` |

## 边界说明

- 本仓库历史中确实存在第三方代码，这一点在 `ACKNOWLEDGEMENTS.md` 中如实记录，不做抹除。
- 与第三方实现相同的部分若属于**事实与规范**（例如 Java class 文件的常量池 tag 编号、Minecraft 配方 JSON 的字段名、工作台界面截图上量出的像素坐标、色带插值的数学定义），则不属于可版权化的表达，规格中直接引用公开规范即可。
- 若后续引入外部贡献者，建议由**未读过历史实现**的人承担实现步骤，并在此目录追加一行记录。
