FRP 厂商开发指南

本指南面向想要为 MoLaunch 开发自定义 FRP 穿透厂商的开发者。通过编写三个配置文件，你可以定义厂商信息、frpc 二进制分发方式、认证流程、API 接口响应规范和配置生成方式。

三文件架构

新设计将厂商配置拆分为三层，各司其职：

文件职责必填
manifest.json厂商元信息 + frpc 分发 + 权限白名单 + 指向 auth/endpoints 文件的指针是
auth.json认证交互层：用户交互方式（授权页 URL、客户端 ID、回调端口等），不含网络请求细节否（auth.type=none 时不需要）
api/endpoints.jsonAPI 规范：认证流程请求/响应解析 + 隧道列表接口 + 响应包裹 + 配置生成模式否（auth.type=none 且手动配置隧道时不需要）
设计理由：不同厂商的接口响应结构各不相同（成功判断、字段命名、数据位置、配置获取方式均有差异）。将接口响应规范做成可配置项，厂商只需在 endpoints.json 中声明即可，启动器自动适配。

快速开始

  1. 创建一个文件夹，命名为你的厂商 ID（如 my-frp-provider）
  2. 在文件夹根目录创建 manifest.json（厂商元信息 + binary + permissions）
  3. 创建 auth.json（认证交互层配置，type=none 时跳过）
  4. 创建 api/endpoints.json（API 接口规范，type=none 时跳过）
  5. 根据分发方式放置 frpc 二进制文件或配置下载地址
  6. 在 MoLaunch 的「Frp 管理 → 厂商列表」中点击「从文件夹安装」「从 ZIP 安装」或「从 URL 安装」

文件夹结构示例：

my-provider/
├── manifest.json      # 厂商元信息
├── auth.json          # 认证交互层（可选）
├── logo.png           # 厂商图标
├── api/
│   └── endpoints.json # API 接口规范（可选）
└── bin/
    └── frpc.exe       # frpc 二进制（bundled 模式）

manifest.json 字段说明

以下是一个完整的 manifest.json 骨架示例：

{
  "id": "my-provider",
  "name": "我的穿透厂商",
  "description": "一个示例 FRP 厂商",
  "version": "1.0.0",
  "author": "作者名称",
  "homepage": "https://example.com",
  "icon": "logo.png",
  "authFile": "auth.json",
  "api": {
    "endpointsFile": "api/endpoints.json"
  },
  "binary": { ... },
  "networkPermissions": { ... },
  "processPermissions": { ... }
}
字段类型必填说明
idstring是厂商唯一标识（小写字母+连字符，如 my-provider）
namestring是显示名称
descriptionstring是简短描述
versionstring是厂商版本号（语义化版本）
authorstring是作者名称
homepagestring否厂商主页 URL
iconstring否图标文件相对路径（建议 128x128 PNG）
authFilestring否认证交互层配置文件路径（默认 auth.json）
api.endpointsFilestring否API 规范文件路径（默认 api/endpoints.json）
binaryobject是frpc 二进制分发配置
networkPermissionsobject否网络权限白名单
processPermissionsobject否进程权限白名单

auth.json 认证交互层

auth.json 只描述用户交互方式，实际的网络请求与响应解析在 endpoints.json 的 authFlows 中定义。按 type 读取对应块，其他块忽略。

{
  "type": "oauth2",

  "oauth2": {
    "authorizeUrl": "https://console.example.com/oauth/authorize",
    "clientId": "your-client-id",
    "clientSecret": "optional-client-secret",
    "scopes": ["tunnel:manage"],
    "redirectPort": 18365
  },

  "deviceCode": {
    "clientId": "your-client-id",
    "clientSecret": "optional-client-secret",
    "scopes": ["tunnel:manage"],
    "pollInterval": 5
  },

  "apiKey": {
    "obtainUrl": "https://example.com/dashboard/api-keys",
    "headerName": "X-API-Key"
  }
}
type字段说明
oauth2authorizeUrl授权页 URL（浏览器打开让用户登录授权）
clientIdOAuth2 客户端 ID
clientSecret客户端密钥（可选，部分厂商需要）
scopes权限范围列表
redirectPort本地回调端口（本地启动 HTTP 服务接收回调）
device_codeclientId客户端 ID
clientSecret客户端密钥（可选）
scopes权限范围列表
pollInterval轮询间隔（秒），默认 5
api_keyobtainUrl获取 API Key 的页面 URL（前端提供跳转入口）
headerNameAPI Key 在请求头中的字段名
none—无需认证，type=none 时不需要 auth.json

endpoints.json API 规范

endpoints.json 是新设计的核心文件，定义厂商 API 的所有接口响应规范。启动器按此配置动态构造请求和解析响应，适配不同厂商的接口差异。

顶层结构

{
  "baseUrl": "https://example.com/api/v1",
  "auth": { ... },
  "authFlows": { ... },
  "envelope": { ... },
  "config": { ... },
  "endpoints": { ... },
  "tunnelFields": { ... }
}

baseUrl 与 auth（token 注入）

baseUrl 是所有 API 请求的基础 URL，必须使用 HTTPS。auth 定义认证 token 如何注入到请求中。

{
  "baseUrl": "https://api.example.com",
  "auth": {
    "headerName": "Authorization",
    "headerPrefix": "Bearer ",
    "headerKeyName": "x-request-public-key"
  }
}
字段说明
headerName附加 token 的请求头字段名（如 Authorization）
headerPrefixtoken 前缀（如 "Bearer "，OpenFRP 无空格前缀时留空）
headerKeyName登录响应中服务器密钥所在的响应头名（解密用，可选）

authFlows（认证流程定义）

定义认证流程的请求参数和响应解析。即使厂商实现不标准，也可通过自定义请求参数与响应解析适配。

支持的占位符（请求体/查询/URL 中替换）：{clientId} {clientSecret} {redirectUri} {code} {codeVerifier} {refreshToken} {deviceCode} {scope} {apiKey} {publicKey} {requestUuid}

oauth2 流程

"oauth2": {
  "token": {
    "method": "POST",
    "url": "{baseUrl}/oauth/token",
    "contentType": "application/x-www-form-urlencoded",
    "body": {
      "grant_type": "authorization_code",
      "code": "{code}",
      "redirect_uri": "{redirectUri}",
      "client_id": "{clientId}"
    },
    "response": {
      "accessToken": { "from": "body", "path": "$.access_token" },
      "refreshToken": { "from": "body", "path": "$.refresh_token" },
      "expiresIn": { "from": "body", "path": "$.expires_in" },
      "errorField": { "from": "body", "path": "$.error" },
      "errorDescription": { "from": "body", "path": "$.error_description" }
    }
  },
  "refresh": {
    "method": "POST",
    "url": "{baseUrl}/oauth/token",
    "contentType": "application/x-www-form-urlencoded",
    "body": {
      "grant_type": "refresh_token",
      "refresh_token": "{refreshToken}",
      "client_id": "{clientId}"
    },
    "response": { ... }
  }
}
refresh 缺失时回退到 token，适配部分厂商用同一端点刷新的场景。

device_code 流程

"device_code": {
  "request": {
    "method": "POST",
    "url": "{baseUrl}/oauth/device/code",
    "contentType": "application/x-www-form-urlencoded",
    "body": { "client_id": "{clientId}", "scope": "{scope}" },
    "response": {
      "deviceCode": { "from": "body", "path": "$.device_code" },
      "userCode": { "from": "body", "path": "$.user_code" },
      "verificationUri": { "from": "body", "path": "$.verification_uri" },
      "pollInterval": { "from": "body", "path": "$.interval" },
      "expiresIn": { "from": "body", "path": "$.expires_in" }
    }
  },
  "poll": {
    "method": "POST",
    "url": "{baseUrl}/oauth/token",
    "contentType": "application/x-www-form-urlencoded",
    "body": {
      "grant_type": "urn:ietf:params:oauth:grant-type:device_code",
      "device_code": "{deviceCode}",
      "client_id": "{clientId}"
    },
    "response": {
      "accessToken": { "from": "body", "path": "$.access_token" },
      "refreshToken": { "from": "body", "path": "$.refresh_token" },
      "expiresIn": { "from": "body", "path": "$.expires_in" },
      "pendingError": "authorization_pending",
      "errorField": { "from": "body", "path": "$.error" }
    }
  }
}

pendingError 是轮询中的"等待中"错误码（如 authorization_pending），遇到此错误继续轮询而非报错。

响应字段提取（FieldExtractor）

from字段说明
bodypath从响应体按 JSONPath 取值（如 $.access_token）
headername从响应头取值（如 OpenFRP 的 token 在 Authorization 响应头）

envelope（响应包裹解析）

厂商 API 响应通常包裹在统一结构中（如 {"flag": true, "msg": "", "data": [...]}）。envelope 定义如何判断成功和提取数据。

"envelope": {
  "successField": "$.flag",
  "successValue": true,
  "errorField": "$.msg",
  "dataField": "$.data"
}
字段说明
successField成功标志字段路径（JSONPath），成功判断时取值与 successValue 比较
successValue成功时的值（支持类型宽松匹配：true/"true"/1 均视为成功）
errorField错误消息字段路径（失败时提取错误描述）
dataField数据字段路径（提取实际数据负载）
各接口可用 endpoints.*.envelope 覆盖全局 envelope。

config（配置生成模式）

定义如何从厂商 API 获取或生成 frpc 配置。三种模式：

"config": {
  "mode": "fields",
  "format": "ini",
  "args": []
}
mode说明
url厂商接口直接返回 frpc 配置字符串，启动器写盘即可（预留 base64/xor/aes 解码扩展点）
fields启动器按 tunnelFields 拼装 ini 配置（从隧道列表接口提取字段）
argsfrpc 以启动参数方式运行（如 OpenFRP -u 密钥 -p 隧道ID），args 为参数模板，支持 {token} {ids} 占位符

endpoints（API 端点定义）

定义具体的 API 端点：账号信息、隧道列表、隧道详情、配置获取。

account（账号信息，可选）

获取授权账号信息，验证授权是否有效。返回的 token 字段可作为 {account.token} 在隧道字段映射中引用。

"account": {
  "method": "POST",
  "path": "/user/info",
  "authType": "bearer",
  "response": {
    "dataField": "$.data",
    "fields": {
      "id": "id",
      "username": "username",
      "email": "email",
      "token": "token"
    }
  }
}

tunnels.list（隧道列表，必填）

获取用户隧道列表。itemsField 支持嵌套展平（如 $.data[*].proxies[*] 从多级数组提取）。

"tunnels": {
  "list": {
    "method": "POST",
    "path": "/frp/api/getUserProxies",
    "authType": "bearer",
    "response": {
      "itemsField": "$.data[*].proxies[*]",
      "tunnelIdField": "id",
      "tunnelNameField": "proxyName",
      "fields": {
        "id": "id",
        "name": "proxyName",
        "type": "proxyType",
        "status": "status",
        "serverHost": { "field": "connectAddress", "split": ":" },
        "serverPort": { "field": "connectAddress", "split": ":" },
        "token": "{account.token}",
        "localHost": "localIp",
        "localPort": "localPort",
        "remotePort": "remotePort",
        "customDomain": "domain"
      }
    }
  }
}

字段映射（FieldMapping）

fields 中的值支持三种形式：

形式示例说明
字符串"proxyName"直接取 item 的该字段值
对象 {field, split}{"field": "connectAddress", "split": ":"}从合并字段按分隔符拆分（如 "host:port" 拆分为 serverHost 和 serverPort）
模板字符串"{account.token}"引用账号信息中的字段（需先调用 account 端点）

tunnels.config（配置获取，可选）

config.mode=url 时使用，厂商接口直接返回 frpc 配置字符串。

"config": {
  "method": "GET",
  "path": "/user/frpc/config",
  "authType": "bearer",
  "query": { "tunnel": "{id}" },
  "response": {
    "dataField": "$.data.config",
    "encoding": "text"
  }
}

frpc 二进制分发（binary）

bundled：随包打包

将 frpc 二进制文件放入厂商文件夹，通过 path 指定相对路径。

{
  "binary": {
    "distribution": "bundled",
    "path": "bin/frpc.exe"
  }
}

url：按需下载

用户首次使用时自动下载 frpc，支持 ZIP 压缩包自动解压。

{
  "binary": {
    "distribution": "url",
    "download": {
      "url": "https://example.com/frpc-windows.zip",
      "sha256": "可选校验值",
      "allowedDomains": ["example.com"],
      "targetPath": "frpc.exe",
      "archive": true
    }
  }
}
字段说明
url下载地址
sha256可选，文件 SHA256 校验值
allowedDomains允许下载的域名白名单
targetPath下载后存放的相对路径（archive=true 时为解压后的目标文件）
archive是否为 ZIP 压缩包（true 时自动解压）

网络权限（networkPermissions）

限制 frpc 可连接的服务器地址，防止厂商恶意连接未知服务器。

{
  "networkPermissions": {
    "allowedServers": ["frps.example.com:7000", "1.2.3.4:7000"],
    "allowCustomServer": false
  }
}
字段说明
allowedServers允许的 frps 服务器地址白名单（域名或 IP[:端口]）
allowCustomServer是否允许用户自定义服务器（false=仅白名单内的服务器）
系统默认厂商始终允许自定义服务器，不受此限制。

进程权限（processPermissions）

限制厂商认证适配器脚本的执行权限。仅当厂商提供自定义认证脚本时启用。

{
  "processPermissions": {
    "allowedCommands": ["node", "python"],
    "timeoutMs": 30000
  }
}
字段说明
allowedCommands允许执行的命令白名单（如 ["node", "python"]）
timeoutMs超时毫秒，默认 30000（30 秒），最大 300000（5 分钟）

安全约束：

  • 命令必须通过 which_canonical 解析后与白名单匹配
  • 非 shell 执行，防止命令注入
  • stdout/stderr 各截断到 1MB
  • 工作目录限制在厂商目录内

完整示例：OpenFRP（非标准厂商）

OpenFRP 是非标准厂商的典型示例：token 在响应 Header、frpc 以启动参数运行、隧道列表嵌套在节点分组中。

关键差异

  • token 在响应头：accessToken 使用 { "from": "header", "name": "Authorization" } 而非 body
  • frpc 启动参数模式：config.mode = "args"，参数模板 ["-u", "{token}", "-p", "{ids}"]
  • 隧道列表嵌套：itemsField = "$.data[*].proxies[*]" 从节点分组中展平提取
  • 合并字段拆分：connectAddress 按 : 拆分为 serverHost 和 serverPort
  • 账号 token 引用："token": "{account.token}" 从账号信息取 frpc 启动密钥

完整配置见 docs/Frp Test/frp/providers/openfrp.json。

安装方式

从文件夹安装

将厂商文件夹（包含 manifest.json）的路径通过「从文件夹安装」按钮选择即可。

从 ZIP 安装

将厂商文件夹打包为 ZIP（manifest.json 在 ZIP 根目录），通过「从 ZIP 安装」按钮选择 ZIP 文件。

ZIP 结构示例：

acme-tunnel.zip
├── manifest.json
├── auth.json
├── logo.png
├── api/
│   └── endpoints.json
└── bin/
    └── frpc.exe

从 URL 安装

将厂商 ZIP 包托管在 HTTPS 服务器上，通过「从 URL 安装」输入下载地址。启动器自动下载并解压安装。

安装后厂商文件存放在 AppData 全局目录下，所有 MoLaunch 实例共享。
